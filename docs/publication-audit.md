# Публикационный аудит и первое объявление

## Подготовка разрешённых материалов

Получите от Юлии сведения, статус, разрешённую точность адреса и разрешение на публикацию изображений. Публичные данные одного объекта хранятся в `src/data/properties/<имя>.toml`, разрешённые веб-изображения и планировка — в `src/media/properties/<id>/`. Схема и обязательные поля: [property-data.md](property-data.md). Постоянные `id` и `slug` не меняйте после публикации.

Для актуального объекта укажите `status = "active"`, `ever_published = true`. `featured = true` добавляет его в подборку главной; `false` оставляет в каталоге и учитывает в первом экране, но не добавляет в подборку. Настройте порядок `photos`, осмысленный `alt`, при необходимости `caption`, `cover` и `floor_plan`. Не подставляйте неизвестные цену, характеристики или фотографии.

Непубличные оригиналы, черновики, документы и данные собственников храните вне репозитория; допустимое локальное удобство — игнорируемая папка `local-private/`. Не кладите их в `public/`, TOML, fixtures или подписи. Флаг `draft` не скрывает содержимое Git: обычный публичный источник с черновиком отклоняется. Для продажи/снятия сохраняйте постоянную ссылку и `ever_published`, меняйте статус на `sold`/`withdrawn`. Прежние поля и медиа не попадают в сборку, однако уже отправленные исходники остаются в истории Git.

## Локальная проверка

Из корня проекта (Python 3.12):

```powershell
python -X utf8 scripts/check.py
python -X utf8 scripts/check_catalog_browser.py
python -X utf8 scripts/check_gallery_browser.py
python -X utf8 scripts/check_client_journeys_browser.py

python -X utf8 scripts/site.py build --base-path / --no-demo --preliminary
python -X utf8 scripts/check_release.py --base-path /

python -X utf8 scripts/site.py build --base-path /yulia-ryazan-realty/ --no-demo --preliminary
python -X utf8 scripts/check_release.py --base-path /yulia-ryazan-realty/
```

Браузерные проверки требуют установленного Chrome и проверяют синтетические сценарии во временных каталогах. `check.py` включает `check_release_tests.py`: он подменяет пути источников и медиа только в процессе теста, не пишет объявления в настоящий `src/data/properties/` и не меняет основной `dist/`. Он проверяет корень и подпапку, пустой каталог, обычные синтетические актуальные/неактуальные объекты и намеренно повреждённые артефакты. Отдельный запуск: `python -X utf8 scripts/check_release_tests.py`.

После подготовки своих материалов откройте локально именно обычную сборку. Проверьте объявление по прямой ссылке, карточку, подборку, фильтры, галерею, планировку, телефон, мобильную ширину и работу без JavaScript. Сверьте каждый снимок, кадрирование, подпись и метаданные. Проверьте canonical/OG и `sitemap.xml`: абсолютный публичный адрес берётся из `site.toml`, независимо от локального базового пути; localhost там недопустим. `noindex, nofollow` сохраняется, настройки Pages не меняются.

## Что разрешает и проверяет аудит

Аудит читает валидированные обычные источники, без `--test-data`. Разрешённый состав рассчитывается явно:

- четыре основные страницы, CSS, веб-фото Юлии, `sitemap.xml` и `.nojekyll`;
- отдельные страницы объектов с `ever_published = true`;
- `catalog.js` и `object.js` только при наличии актуальных объектов;
- только перечисленные фотографии и планировки актуальных объектов по пути `property-media/public/<id>/...`.

Для проданных и снятых объектов допускается только минимальное содержимое без старых полей и медиа; их URL отсутствуют в sitemap. Sitemap содержит четыре основных раздела и только актуальные опубликованные объекты. Fixtures, демо и публичные черновики не допускаются. Нет разрешения на произвольное поддерево `dist/`: лишние и недостающие файлы, даже пустые лишние каталоги, ссылки/junctions, посторонние копии из `public/`, подменённые ресурсы и HTML отклоняются.

Проверяются ссылки и якоря с учётом базового пути, телефон, canonical, Open Graph и `noindex, nofollow`. Внешние ссылки допускаются только из предусмотренных полей контактов и актуальных объектов; аудит не открывает внешний видеосервис и не подтверждает его доступность. Дополнительно вся сборка сравнивается с повторной чистой генерацией из тех же источников во временном `.check-release-reference-*/dist`. Это обнаруживает изменённые HTML/JSON, метаданные и устаревший вывод. Проверяемая папка не изменяется; временная удаляется после проверки. Для другого уже созданного артефакта можно указать `--output <путь>` и соответствующий `--base-path`. Обычный workflow использует прежний вызов без аргументов для подпапки проекта.

## Что нужно проверить вручную перед отправкой

Аудит обнаружит посторонний `owners.csv`, `.env`, фиктивную страницу, тестовый ресурс или добавленный текст в артефакте. Он **не определяет**, разрешено ли публиковать текст, фото или внешний URL, уже внесённые в допустимый источник. Сравнение с генератором не является независимой проверкой всех ошибок самого генератора; это дополняют сценарные и браузерные тесты. Перед коммитом просмотрите `git diff`, новые файлы и затем `git diff --cached`:

- проверьте адреса и их точность, имена, телефоны собственников, документы, комментарии, описания, подписи, alt, структурированные данные и исходный HTML;
- просмотрите сами изображения и планировки: лица, документы, номера квартир, отражения, персональные сведения; отдельно проверьте и удалите непредназначенные для публикации EXIF/GPS и другие метаданные;
- проверьте все исходники, включая неиспользуемые фото: не попавший в сайт отслеживаемый файл всё равно станет доступен в публичном Git;
- исключите сборку, кеши, скриншоты, черновики, секреты и служебные материалы. `.gitignore` не скрывает уже отслеживаемые файлы, а `noindex` не защищает доступ.

Коммит, push и публикация выполняются отдельным разрешённым действием после просмотра состава. После публикации проверьте результат Actions, прямую ссылку на объект, главную, каталог, фото/планировку, телефон на реальном телефоне, sitemap, canonical/OG, старые ссылки и сохранение noindex. Удаление объекта из текущей сборки не удаляет уже публичные копии и историю Git. Снятие `noindex` требует отдельного решения и изменения проверок.
