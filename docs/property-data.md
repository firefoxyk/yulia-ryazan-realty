# Объявления: данные и статическая сборка

Это инструкция к технической основе каталога. **Правила полей и публикации ниже предварительные**, кроме прямо заданных заказчиком правил статусов и постоянных ссылок. Перед загрузкой реальных объявлений подтвердите их с Юлией. Реальных объявлений в проекте пока нет.

## Где хранятся файлы

| Назначение | Папка |
| --- | --- |
| Публичные данные | `src/data/properties/*.toml`: один объект — один файл |
| Разрешённые для публикации изображения объектов | `src/media/properties/` |
| Синтетические примеры | `tests/fixtures/properties/` |
| Нейтральные ресурсы тестов | `tests/fixtures/media/` |
| Необязательная локальная рабочая папка | `local-private/`, исключена из Git и никогда не читается сборкой |
| Результат | `dist/objects/<slug>/index.html` и выбранные ресурсы в `dist/property-media/` |

Обычные страницы, телефон и портрет Юлии используют прежние файлы. `site.toml` не изменён.

Изображения объектов намеренно находятся **вне `public/`**. Всё содержимое `public/` копируется как статические ресурсы. В `src/media/properties/` сборщик выбирает только файлы, на которые ссылаются актуальные объекты: список фотографий и планировку. Файлы проданных, снятых и черновых объектов сами по себе не копируются.

Предпочтительная организация фото: `src/media/properties/<id>/01.jpg`, `02.jpg`, `plan.png`. В TOML указываются относительные пути `<id>/01.jpg`. В имени файла используйте латиницу, цифры, дефис, подчёркивание и точку. Обратные слеши Windows, абсолютные пути, URL, `..` и выход через символические ссылки запрещены.

Поддержаны JPEG, PNG, WebP и простой SVG без скриптов, ссылок и вложений. SVG предназначен прежде всего для собственных нейтральных схем. Расширение и сигнатура растрового файла проверяются, но это не полноценный декодер изображений: реальную читаемость, качество и размер фото дополнительно проверяйте в браузере. Метаданные фотографий нужно проверить до помещения в публичный репозиторий.

## Пример: синтетическая квартира, не реальное объявление

Этот пример не следует сохранять в публичную папку как настоящее предложение. Для проверки уже есть отдельные fixtures.

```toml
id = "example-apartment-001"
slug = "example-apartment-001"
status = "active"
ever_published = true
published_at = 2026-11-04
featured = true

type = "apartment"
market = "primary"
title = "Тестовая квартира — не объявление"
price = 4200000
currency = "RUB"
city = "Тестовый город"
district = "Условный район"
public_address = "Только разрешённая часть адреса"
description = """
Синтетический текст для иллюстрации формата.
Вторая строка описания.
"""
area_m2 = 54.5
rooms = 2
floor = 3
floors = 9
cover = 1
floor_plan = "example-apartment-001/plan.png"

[features]
"Отделка" = "Пример публичной характеристики"

[[photos]]
path = "example-apartment-001/01.jpg"
alt = "Описание первого изображения"
caption = "Первая фотография"

[[photos]]
path = "example-apartment-001/02.jpg"
alt = "Описание второго изображения"
caption = "Главная фотография, вторая по порядку"
```

Указанные изображения нужно подготовить до сборки. Отсутствующие файлы вызывают ошибку; сам пример не создаёт изображения.

## Поля и временные решения

### Идентификатор, адрес и статус

- `id`, `slug`, `status`, `ever_published` обязательны у любой записи.
- `id` — постоянный уникальный идентификатор.
- `slug` — отдельная постоянная часть адреса: `<base>/objects/<slug>/`.
- `id` и `slug` содержат строчные латинские буквы, цифры и одиночные дефисы между частями; максимум 80 символов. Адрес `demo` зарезервирован старой демонстрацией.
- Повторы `id` и `slug` проверяются среди всех загруженных записей, включая неактуальные и синтетические.
- Не меняйте `id` и `slug` при редактировании текста, цены, статуса или фото. Не используйте их для другого объекта после снятия старого.
- `ever_published` — предварительный явный признак закреплённой публичной ссылки. Для первой сборки объекта `active` он должен быть `true`; после публикации остаётся `true`.
- Автоматического журнала публикаций нет. Сборщик не угадывает прошлое по Git и не меняет TOML. Разработчик отвечает за сохранение этого признака и прежних адресов; постоянство полей при ручной замене идентификатора не может быть восстановлено автоматически.
- `published_at` необязателен: дата TOML либо строка `YYYY-MM-DD`. Это подпись даты, не механизм отложенной публикации.
- `featured` необязателен, по умолчанию `false`: актуальный объект с `true` входит в подборку на главной.

### Основные сведения

Для статуса `active` дополнительно обязательны `type`, `title`, `city`, `description`. Пустые обязательные строки не допускаются. Пока это минимальный технический набор для сборки, а не утверждённый редакционный стандарт публикации.

- `type`: `apartment` — квартира, `house` — дом, `land` — участок.
- `market` необязателен: `primary` или `secondary`, отдельно от типа. Для квартиры и дома применим, для участка на этом этапе не допускается.
- Новые типы вводятся осознанно в `TYPES` и `APPLICABLE` в `scripts/property_data.py`; неизвестные значения не принимаются молча.
- `price` необязателен: целое положительное число рублей. Ноль, отрицательная цена, дробное число, бесконечность и логические значения недопустимы.
- **Временное правило отсутствующей цены:** показывается «Цена по запросу», без выдуманного числа.
- `currency` необязателен; пока разрешён только `RUB`.
- `city` — город или населённый пункт; `district` — необязательное уточнение района.
- `public_address` необязателен: только разрешённая к публикации часть адреса. Это не поле для хранения тайного точного адреса.
- `description` — обычный текст. HTML не исполняется; строки выводятся как абзацы.
- Неизвестные поля отклоняются. Не добавляйте в схему телефоны собственников, документы и служебные заметки.

### Характеристики

| Поле | Значение | Где применяется |
| --- | --- | --- |
| `area_m2` | Положительная площадь объекта, м² | Квартира, дом |
| `plot_area` | Положительная площадь участка | Дом, участок |
| `plot_unit` | `m2`, `sotka` или `ha`; обязательно при наличии `plot_area` | Дом, участок |
| `rooms` | Целое число от 0; 0 отображается как «Студия» | Квартира, дом |
| `floor` | Целое число от 0, не больше этажности, если она задана | Квартира |
| `floors` | Положительное целое число | Квартира, дом |
| `features` | Таблица дополнительных публичных характеристик «текстовая подпись = текст» | По необходимости |

Все характеристики необязательны. Неприменимые к типу поля не нужны и при ошибочном заполнении вызывают понятную ошибку. Пропущенные поля не получают выдуманных значений. В TOML нет `null`: отсутствующее необязательное поле просто не записывайте. Если необязательное текстовое поле записано, оно не должно быть пустым.

### Фото и дополнительные материалы

- `photos` — упорядоченный список таблиц `[[photos]]`.
- У каждой фотографии обязательны `path` и непустой `alt`; `caption` необязателен.
- `cover` — индекс главной фотографии, **с нуля**. Если не указан, главной становится первая фотография; порядок списка при этом не меняется.
- Если фото нет, поле `photos` можно не задавать. `cover` в этом случае не задаётся.
- **Временное правило отсутствующих фото:** карточка и страница остаются рабочими, показывая нейтральный текст «Фотографии пока нет». Случайная картинка не подставляется.
- На странице выводится главная фотография и простой список ссылок на фото в исходном порядке с подписями. Интерактивной галереи пока нет.
- `floor_plan` — необязательный путь к изображению планировки в том же каталоге ресурсов.
- `video_url` и `tour_url` — необязательные полные HTTPS-адреса без пароля, имени пользователя и управляющих символов. Они выводятся ссылками, не встраиваются.
- Наличие внешнего видео или тура проверяется вручную; сетевых запросов к ним сборщик не делает.

## Статусы и старые ссылки

| Статус | Каталог и главная | Страница и ресурсы |
| --- | --- | --- |
| `active` — в продаже | Каталог; главная только при `featured = true` | Отдельная полноценная статическая страница; копируются только используемые фото и планировка |
| `sold` — продано | Отсутствует | При `ever_published = true` — минимальная страница «Объект продан», каталог и контакты |
| `withdrawn` — снято | Отсутствует | При `ever_published = true` — минимальная страница о снятии, каталог и контакты |
| `draft` — черновик | Отсутствует | В публичной папке — ошибка сборки; разрешён только для синтетических fixtures, которые не генерируют страницу |

Для никогда не опубликованного `sold` или `withdrawn` с `ever_published = false` отдельная страница не создаётся.

Минимальные старые страницы **не выводят прежние название, цену, адрес, описание и фото, включая метаданные страницы**. Прежние ресурсы не копируются только ради неактуальной записи. Допустимый состав расширенной старой страницы остаётся вопросом для согласования.

Для старой ссылки достаточно минимальной записи:

```toml
id = "example-apartment-001"
slug = "example-apartment-001"
status = "sold"
ever_published = true
```

Если в неактуальной записи оставлены необязательные сведения и пути, они всё равно валидируются. Уберите ненужные публичные поля перед удалением их исходных ресурсов.

**Возврат ранее опубликованного объекта в черновик:** сборщик отклоняет `draft` с `ever_published = true`. До согласования оставьте в публичной папке минимальную запись `withdrawn` с прежними `id`, `slug` и `ever_published = true`, а непубличную рабочую версию храните отдельно. Не сбрасывайте признак публикации ради обхода проверки.

## Безопасная работа с непубличными материалами

Предпочтительно хранить настоящие черновики и служебные материалы **вне репозитория**, в доступном только вам локальном хранилище. Допустима папка `local-private/` в проекте для удобства: она исключена через `.gitignore`, не читается генератором и не копируется в `dist/`.

Это защита от случайного добавления, **не шифрование и не контроль доступа**. Файлы остаются доступны другим пользователям компьютера и резервным копиям. `git add -f` может обойти исключение. Если файл уже отслеживается Git, `.gitignore` его не скроет. Удаление из последнего коммита не очищает историю.

Непубличные данные нельзя класть в `public/`, публичные TOML, fixtures, подписи и метаданные изображений. Флаг `draft` не делает содержимое публичного репозитория тайным. Сборщик отклоняет такую запись в публичной папке, но не является универсальным сканером персональных данных и не заменяет просмотр изменений перед push.

В fixture черновика есть только явно синтетические маркеры для теста. Это не образец хранения реальных непубличных материалов в Git.

## Как добавить или изменить объект через Codex

1. Получите от Юлии сведения, статус, разрешённую точность адреса и разрешение на публикацию фото. Отделите непубличные сведения до передачи файлов в проект.
2. Попросите Codex создать один файл в `src/data/properties/` и подготовить разрешённые изображения в `src/media/properties/<id>/`.
3. Согласуйте постоянные `id` и `slug`. Для первого вывода `active` укажите `ever_published = true`. Явно выберите `featured`.
4. Для редактирования меняйте данные этого файла. Карточки, главная и отдельная страница будут обновлены одной сборкой; HTML вручную переписывать не нужно.
5. Для продажи или снятия меняйте статус, сохраняя ссылку и признак прежней публикации. Не удаляйте публичную минимальную запись старой ссылки.
6. Выполните проверки и сборки, откройте страницу напрямую и обновите её в браузере.
7. Перед отправкой в Git просмотрите diff, staged-файлы, исходные фото и их метаданные. Убедитесь, что нет персональных данных собственников, непубличных черновиков и случайных ресурсов.
8. Коммит, push и публикация выполняются только отдельным согласованным действием.

Для безопасного запуска без прежней демонстрационной карточки:

```powershell
py -3 scripts/check.py
py -3 scripts/site.py build --no-demo
py -3 scripts/site.py preview
```

Для проверки подпапки:

```powershell
py -3 scripts/site.py build --base-path /yulia-ryazan-realty/ --no-demo
py -3 scripts/site.py preview --base-path /yulia-ryazan-realty/
```

Результат сборки полностью заменяет предыдущий `dist/`. Ошибочные данные проверяются **до удаления** предыдущей сборки; команда завершается с ошибкой и именем файла и поля. Прежняя сборка при этом не становится результатом неуспешной команды — исправьте данные и повторите сборку.

## Тестовый режим

Обычная сборка не читает `tests/fixtures/`. Отдельный явный режим:

```powershell
py -3 scripts/site.py dev --test-data
```

Он требует включённого демо (`include_demo = true` и без `--no-demo`). При отключённом демо флаг `--test-data` не подключает fixtures. Исходные TOML и папка tests никогда не копируются в сайт; используются только выбранные ресурсы активных тестовых объектов, в отдельном пространстве `property-media/test/`.

Локальные адреса в тестовом режиме:

- `http://127.0.0.1:8000/catalog/`
- `http://127.0.0.1:8000/objects/test-apartment/`
- `http://127.0.0.1:8000/objects/test-house/`
- `http://127.0.0.1:8000/objects/test-land/`
- `http://127.0.0.1:8000/objects/test-sold/`
- `http://127.0.0.1:8000/objects/test-withdrawn/`

У `test-draft` страницы нет. Все тестовые карточки и страницы явно помечены как примеры, не объявления. Не публикуйте такую сборку.

Прежний деморежим `objects/demo/` сохранён. В обычном режиме при отсутствии реальных актуальных объектов и включённом демо показывается прежний пример карточки. В новом тестовом режиме его заменяют карточки данных. Если появились реальные актуальные объекты, прежняя карточка не добавляется в каталог рядом с ними. Главная выводит только отмеченные актуальные объекты; пустая подборка скрывается.

## Что проверено и что остаётся

`py -3 scripts/check.py` запускает прежние проверки страниц и новый набор `scripts/check_properties.py`.

Проверяется: статусы, выборка главной, старые ссылки, отсутствие черновых маркеров и ресурсов, уникальность, ошибки обязательных полей и чисел, пути, опасный SVG, HTTPS-ссылки, экранирование текста, отсутствие необязательных полей, постоянный адрес, порядок фото и главная фотография, реальное HTTP-открытие страниц и ресурсов в корне и подпапке. Также проверяется, что ошибка данных не стирает последнюю рабочую сборку.

Тест реального выхода через символическую ссылку выполняется только если ОС разрешает создать такую ссылку; иначе он явно отмечается как пропущенный. Проверка `resolve()` и границ каталогов реализована независимо от этого ограничения среды.

Полноценная галерея, фильтры, сортировка, динамические категории/рынки, выбор окончательных обязательных полей, окончательный состав старой страницы, допустимые переходы статусов и реальные материалы остаются следующими этапами. Не считаются проверенными внешний видеосервис, виртуальный тур и опубликованный хостинг.
