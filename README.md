# Сайт Юлии Ларюшкиной

Персональный сайт Юлии Ларюшкиной — агента по недвижимости в Рязани. Подготовлены визуальный вариант, тексты, телефон и фотография, файловая основа объявлений, адаптивный каталог с фильтрами и сортировкой, страницы объектов с галереей. Дизайн и тексты предназначены для просмотра и согласования. Требования к будущей версии сохранены в `docs/requirements.md`.

## Технологии

HTML, CSS и небольшой генератор на стандартной библиотеке **Python 3.12 или новее**. Python нужен только разработчику для сборки и локального просмотра. На хостинг загружаются готовые HTML и CSS из `dist/`; Python, сервер приложения и база данных на хостинге не нужны.

Внешних зависимостей нет: установка пакетов, npm и lock-файл не требуются. Фильтры и сортировка работают обычным JavaScript в браузере. Генератор создаёт настоящий `index.html` для каждого адреса, поэтому прямые ссылки работают без SPA-перенаправлений.

## Начало работы на Windows

Установите Python 3.12+ с python.org, включая Python Launcher. Откройте PowerShell в папке проекта:

```powershell
py -3 --version
py -3 scripts/site.py dev
```

Откройте `http://127.0.0.1:8000/`. Остановка — Ctrl+C. Команда `dev` сначала собирает сайт, затем запускает локальный просмотр. После редактирования исходников остановите и повторите команду: автоматического обновления нет. Если команда `py` недоступна, используйте `python` нужной версии.

Сборка, проверка и просмотр готового результата:

```powershell
py -3 scripts/check.py
py -3 scripts/site.py build
py -3 scripts/site.py preview
```

`preview` ничего не пересобирает. Порт можно изменить: `--port 8080`. Локальный сервер слушает только `127.0.0.1`; это инструмент разработки. Не открывайте HTML через `file://`: проверяйте сайт по HTTP.

## Корень домена и GitHub Pages

Постоянная настройка находится в `site.toml`:

```toml
base_path = "/"
include_demo = true
```

Для размещения в подпапке задайте `base_path = "/yulia-ryazan-realty/"`. Можно временно переопределить путь без изменения конфигурации:

```powershell
py -3 scripts/site.py build --base-path /yulia-ryazan-realty/
py -3 scripts/site.py preview --base-path /yulia-ryazan-realty/
```

Откройте:

- `http://127.0.0.1:8000/yulia-ryazan-realty/`
- `http://127.0.0.1:8000/yulia-ryazan-realty/catalog/`
- `http://127.0.0.1:8000/yulia-ryazan-realty/about/`
- `http://127.0.0.1:8000/yulia-ryazan-realty/contacts/`
- `http://127.0.0.1:8000/yulia-ryazan-realty/objects/demo/`

Последний адрес открывайте напрямую и обновляйте страницу. Путь при сборке и просмотре должен совпадать. Для возврата к корню повторите обе команды с `--base-path /`.

В `dist/` всегда находятся файлы относительно корня сайта, без дополнительной папки `yulia-ryazan-realty`. При будущей публикации на GitHub Pages содержимое `dist/` будет артефактом сайта; на обычном хостинге его нужно положить в выбранную корневую папку или подпапку. Хостинг должен отдавать `index.html` из каталогов. Ссылки и CSS получают префикс при сборке. Для будущих изображений и скриптов используйте в HTML `${base}images/...` и `${base}assets/...`; в CSS используйте пути относительно самого CSS-файла.

Файл `.nojekyll` добавляется автоматически. Предварительная публикация на GitHub Pages настроена через `.github/workflows/pages.yml`; на хостинг передаётся только проверенный `dist/`, а не исходный репозиторий.

## Структура

```text
site.toml                     базовый путь и включение демо
scripts/site.py               генерация и локальный просмотр
scripts/check.py              интеграционные проверки
src/templates/layout.html     общая шапка, навигация, подвал, метаданные
src/pages/                    главная, каталог, обо мне, контакты
src/templates/portrait.html   общий блок фотографии или нейтральной заглушки
src/templates/portrait-placeholder.html запасная композиция без фото
src/demo/                     карточка, страница объекта, контакты и SVG-заглушка
src/data/contacts.toml         единый источник имени и номера телефона
public/assets/styles.css      базовые адаптивные стили
public/images/                место для будущих фотографий
dist/                         результат сборки, исключён из Git
```

Генератор использует `string.Template`: `${base}` — базовый путь, `${property_cards}` и `${property_section}` — карточки и подборка, `${portrait}` — общий портрет. Буквальный знак доллара в шаблонах записывайте как `$$`. HTML-шаблоны редактирует разработчик; текст из TOML экранируется, адреса ресурсов и внешние ссылки проверяются при сборке.

Каждая сборка заменяет `dist/`. Не редактируйте эту папку вручную и не храните в ней исходные материалы.

## Временные разделы и подготовка к запуску

Первый экран, подборка объектов, блоки покупателя и собственника, краткое знакомство и связь расположены именно в таком порядке; далее идёт подвал. Подборка «Актуальные предложения» формируется из актуальных записей с `featured = true`; пустая подборка скрывается. Реальных объявлений пока нет. Прежняя демонстрационная карточка сохранена как запасной пример при включённом демо; без демо она и её ресурсы отсутствуют.

В публичных текстах используется безопасная формулировка **Рязань**, с особым вниманием Советскому району. Перед полноценным запуском подтвердите у Юлии перечень услуг и территорию работы. Работа по Рязанской области пока не подтверждена; упоминания области убраны из публичных шаблонов. `docs/requirements.md` сохранён как ранее подготовленный документ: исторические формулировки о территории в нём требуют последующего согласования и не используются как основание заявлять работу по области.

Тексты о Юлии, покупке и продаже квартир, новостройках, вторичном рынке и внимании к Советскому району подготовлены только по материалам заказчика. Прежний блок услуг адаптирован в два сценария — для покупателя и собственника, без дублирования тех же действий отдельной карточкой сопровождения. Стаж, статистика сделок, достижения, гарантии и отзывы не придуманы; форм сбора данных нет.

Сотрудничество с агентством «Новоселье», описание услуг, возможность обращения к наставнику и специалистам, участие специалистов и порядок проверки документов — материалы для согласования с Юлией перед публикацией, а не независимо проверенные факты. Юлии не приписывается самостоятельная юридическая проверка. Удаление служебных надписей из интерфейса и отключение демо не означают утверждение этих текстов. Вопросы согласования хранятся в документации, а не на страницах для посетителя.

Контакты хранятся в `src/data/contacts.toml`: номер `+7 (965) 712-78-48`, ссылка `tel:+79657127848`, полное имя. После изменения номера в одном файле требуется пересборка. Генератор проверяет формат и соответствие отображаемого номера ссылке. Звонок доступен в шапке, подвале, на главной и в контактах. Перед полноценным запуском подтвердите актуальность номера у Юлии. Открытие приложения звонка и реальный вызов проверяются на устройстве отдельно.

По прежней информации заказчика, Telegram и WhatsApp используются с этим же номером, но проверенных ссылок нет. Поэтому блок переписки и предложение сначала позвонить, чтобы узнать способ написать, убраны с публичной страницы: сейчас показан только звонок. Для Telegram нужен подтверждённый адрес профиля, для WhatsApp — проверенная ссылка и переход на устройстве. Для MAX предусмотрен необязательный `max_url` в `src/data/contacts.toml`, сейчас он пуст. Непроверенные профили и ссылки не придуманы.

Фотография квартиры остаётся собственной векторной иллюстрацией. Цена, название, местоположение и характеристики демонстрационной карточки условные; карточка явно помечена как пример, а не объявление.

### Фотография Юлии

На главной и странице «Обо мне» используется `public/images/yulia-laryushkina.jpg`: JPEG 900 × 1125 px, 167 858 байт (около 164 КиБ), качество JPEG 85. Веб-версия подготовлена из переданного файла `photo_2026-11-04_18-56-07.jpg` (1122 × 1402 px, 209 829 байт). Выполнены только пропорциональное уменьшение и сжатие: без ретуши, генерации, изменения внешности и дополнительного кадрирования самого файла. Оригинал в Downloads не изменён.

Генератор подключает этот файл на обеих страницах с alt «Юлия Ларюшкина, агент по недвижимости в Рязани» и размерами 900 × 1125, учитывая базовый путь. Если файла нет, остаётся нейтральная композиция с инициалами. После замены фотографии требуется пересборка. Портрет является реальным материалом: `include_demo = false` и `--no-demo` его не удаляют. Не нужно помещать неоптимизированный оригинал в `public/`.

Для фото используются отдельные рамки и позиции на компьютере и телефоне. В Chrome проверены ширины 360, 390 и 1280 px: лицо и глаза видимы полностью. Дополнительно проверяется загрузка фото из подпапки без демонстрационных объектов. Скриншоты находятся в `artifacts/screenshots/`; физический телефон и другие браузеры потребуют отдельного просмотра.

`objects/demo/` — демонстрация оформления и маршрутизации. Чтобы убрать демонстрационные страницы, карточки, условные данные, SVG квартиры и служебные подписи, установите `include_demo = false` в `site.toml` и пересоберите сайт. Однократный вариант: `py -3 scripts/site.py build --no-demo`. Если нет реальных актуальных объектов, каталог получает пустое состояние, а подборка на главной скрывается. Реальные записи объектов, тексты, фотография Юлии и телефон остаются. Проверка гарантирует отсутствие старых страниц и данных демонстрационных объектов после пересборки. Это ещё не готовый к запуску сайт: нужно согласовать тексты и условия публикации.

Все страницы содержат `noindex, nofollow`. Служебные надписи о предварительной версии и необходимости согласования не выводятся ни в одном режиме. Отдельный флаг `--preliminary` сохранён для совместимости с workflow: он принудительно отключает демо и тестовые данные, но не добавляет видимых пометок и не меняет индексацию. В режиме разработки остаётся только баннер «Демонстрационный режим · объекты не являются объявлениями» и обозначения самих примеров. Снятие служебных пометок не означает согласование текстов. Индексация автоматически не включается ни одним режимом; решение о ней принимается отдельно. `noindex` не ограничивает доступ: сайт публичный.

## Предварительная публикация на GitHub Pages

Адрес: https://firefoxyk.github.io/yulia-ryazan-realty/

```powershell
py -3 scripts/check.py
py -3 scripts/site.py build --base-path /yulia-ryazan-realty/ --no-demo --preliminary
py -3 scripts/check_release.py
py -3 scripts/site.py preview --base-path /yulia-ryazan-realty/
```

Workflow запускается после push в `main` или вручную из Actions. Он использует Python 3.12 и только официальные действия GitHub: проверки → предварительная сборка → аудит → загрузка `dist/` → Pages. В Settings → Pages источником должен быть GitHub Actions. Исходники, fixtures, документы, локальные скриншоты и оригиналы фотографий в артефакт сайта не попадают.

Аудит `scripts/check_release.py` разрешает ровно четыре HTML-страницы (главная, каталог, обо мне, контакты), CSS, веб-фотографию Юлии, `sitemap.xml` и `.nojekyll`. Проверяются базовый путь, ссылки, телефон, canonical, Open Graph, четыре основных URL sitemap, отсутствие объектов и служебных надписей, наличие `noindex, nofollow`. Это намеренное ограничение **текущего предварительного этапа**: перед публикацией реальных объявлений потребуется отдельно изменить аудит и согласовать переход к следующему этапу. Каталог пока сообщает «Пока здесь нет опубликованных объектов.» и предлагает связаться с Юлией. Пустая подборка на главной скрыта.

Первый экран учитывает весь актуальный каталог, независимо от `featured`: при наличии реальных активных записей показывает «Недвижимость в Рязани», приглашает посмотреть предложения или рассказать Юлии о поиске; основная кнопка — каталог, вторичная — контакты. Без актуальных записей заголовок «Ищете недвижимость в Рязани или планируете продажу?», основное действие — связь с Юлией; каталог доступен в навигации и блоке покупателя. Только тестовые активные записи дают явное пояснение о тестовых примерах; прежняя демокарточка не считается реальным предложением. Формулировки об услугах и агентстве по-прежнему требуют согласования.

Тексты об услугах, сотрудничестве с агентством и участии специалистов ещё требуют согласования с Юлией. Ни деморежим, ни отсутствие его объектов не подтверждают эти сведения. После push проверяйте результат workflow и фактическое открытие сайта; наличие коммита само по себе не подтверждает публикацию. Видимость репозитория и собственный домен workflow не меняет.

Визуальный ориентир — `https://firefoxyk.github.io/yulia-laryushkina/`. Новый вариант использует светлую палитру, глубокий бирюзовый акцент и выразительные заголовки. На сайте используются только локальные ресурсы: системные Georgia/Segoe UI/Arial и собственные HTML/CSS/SVG. Внешние шрифты, фотографии и скрипты не загружаются. На телефоне все пункты навигации видимы без раскрывающегося меню; движения отключаются через `prefers-reduced-motion`.

Локальные скриншоты визуальной проверки сохраняются в `artifacts/screenshots/`. Папка `artifacts/` исключена из Git и не копируется в сборку.

## Проверки

`py -3 scripts/check.py` без внешних пакетов собирает сайт во временной папке и проверяет по HTTP:

- все пять страниц с демо и четыре страницы без демо в корне и подпапке `/yulia-ryazan-realty/`;
- прямую загрузку и повторное открытие каждого адреса;
- внутренние ссылки, CSS и наличие цели ссылки «К содержимому»;
- настоящие ответы 404 для отсутствующих адресов;
- отключение демо, удаление его страницы и SVG, отсутствие карточек, условной цены и служебных подписей при пересборке;
- соответствие всех `tel:`-ссылок единому файлу контактов;
- наличие реальных текстов и телефона также в сборке без демо;
- подключение портрета только при наличии файла и корректные пути к изображению;
- отсутствие вымышленных ссылок Telegram, WhatsApp и MAX.

Мобильный вид проверьте в браузере на ширине 360 и 390 px: навигация должна переноситься, текст и кнопки помещаться без горизонтальной прокрутки, клавиатурный фокус быть видимым. Автоматическая HTTP-проверка не заменяет визуальную проверку.

## Дальнейшее обновление

Подготовлена файловая основа объявлений: один TOML в `src/data/properties/`, разрешённые изображения — в `src/media/properties/`, вне автоматически копируемой папки `public/`. Статусы, уникальные адреса, проверка данных и минимальные страницы уже подключены к сборке. Описание полей, предварительные решения, правила черновиков и пошаговая инструкция — в [docs/property-data.md](docs/property-data.md).

Синтетические квартира, дом, участок, проданный, снятый объект и черновик находятся в `tests/fixtures/`. Обычная сборка их не читает. Локальный просмотр: `py -3 scripts/site.py dev --test-data` при включённом демо. `--no-demo` исключает fixtures даже при переданном `--test-data`. Проверки данных автоматически входят в `py -3 scripts/check.py`.

1. Юлия передаёт подтверждённые сведения и фотографии разработчику.
2. Разработчик передаёт Codex задачу обновить исходники и данные в репозитории.
3. Разработчик проверяет изменения, сборку, страницы и мобильный вид.
4. После отдельного согласования выполняются коммит, push и публикация.

На следующем этапе нужно подтвердить предварительные обязательные поля, правила публикации без цены или фото, поведение ранее опубликованного черновика, окончательное содержание старых страниц, обработку фотографий и правила каталога. Тип объекта и первичный/вторичный рынок хранятся отдельно. Галерея проверяется на изолированных тестовых материалах; реальные объявления пока не добавлены.

## Каталог и локальная проверка

Каталог показывает только `active` с закреплённой опубликованной ссылкой. Карточки расположены сеткой (три колонки на широком экране, две на среднем, одна на телефоне). Изображения каталога имеют рамку 4:3; главная сохраняет прежнее оформление. Категории и рынок формируются только из актуальных записей. Данные фильтрации — минимальный набор публичных полей, без описаний и служебных сведений.

Реализованы тип, рынок, цена от/до, поиск по городу/району/разрешённой части адреса, точное число комнат, диапазоны площади объекта и участка. Площадь объекта задаётся в м², площадь участка — в сотках; единица указана у обоих полей диапазона. 1 сотка = 100 м². Для поиска исходные м² делятся на 100, гектары умножаются на 100, сотки остаются без изменения. Пересчёт выполняется десятичной арифметикой при сборке, браузер сравнивает включительные границы в сотках. При использовании параметра объект без значения исключается; цена «по запросу» исключается только при заданном ценовом диапазоне. При смене типа неприменимые и недоступные параметры очищаются с пояснением. Остальные фильтры не сужают варианты типов и рынка.

В карточках каталога и на подробной странице площадь участка показана в сотках: например, 500 м² → «5 сот.», 805,3 м² → «8,053 сот.», 0,15 га → «15 сот.». Фиксированное округление не применяется, лишние конечные нули убираются, десятичный разделитель — запятая. Исходные TOML не меняются. Карточки на главной сохраняют прежнее представление единиц.

Сортировки: устойчивый порядок каталога по `id`, цена по возрастанию/убыванию, дата публикации по убыванию. Без цены — в конце в обоих направлениях; без даты — после датированных. При отсутствии всех дат сортировка по новизне не предлагается. Равные значения сохраняют порядок каталога.

Фильтры обновляют результат при изменении полей; кнопка «Показать объекты» также доступна. Отрицательные числа, дробная цена и обратные диапазоны дают ошибку, результаты скрываются до исправления или сброса. Нет актуальных объектов — согласованный пустой каталог без фильтров. Нет совпадений — отдельное сообщение, сброс и контакты. На телефоне параметры изначально свёрнуты в доступный с клавиатуры блок. Без JavaScript видны все карточки и ссылки, элементы фильтрации скрыты. Внешних сервисов и зависимостей нет.

```powershell
py -3 scripts/site.py dev --test-data
# http://127.0.0.1:8000/catalog/
py -3 scripts/check.py
py -3 scripts/check_catalog_browser.py
```

Последняя команда отдельно запускает установленный Chrome/Chromium (можно задать `BROWSER_PATH`) и проверяет реальные фильтры, сортировку, отсутствие JS, клавиатуру, пустые состояния и ширины 360/390/1280 в корне и подпапке. Браузерная проверка не запускается автоматически в CI и не подменяется Python-тестами. Скриншоты: `artifacts/screenshots/catalog-*`. Отсутствие браузера считается ограничением проверки, а не успехом.

Синтетических актуальных объектов шесть: по две квартиры, дома и участка; есть одинаковые цены и даты, студия, разные местоположения, пропущенные характеристики, фото и цены. Проданный, снятый и черновик изолированы вместе с ними в `tests/fixtures/`. Обычная сборка fixtures не читает. Сборка для предварительной публикации:

```powershell
py -3 scripts/site.py build --base-path /yulia-ryazan-realty/ --no-demo --preliminary
py -3 scripts/check_release.py
```

В текущей предварительной сборке нет реальных объектов, поэтому отсутствуют также метаданные фильтров и `assets/catalog.js`. Аудит по-прежнему допускает только четыре страницы, CSS, фото Юлии и `.nojekyll`. Перед настоящими объявлениями отдельно согласуйте правила каталога и измените аудит публикации; `noindex` не снимается автоматически. Подробные предварительные решения — в `docs/property-data.md`.

## Страница объекта и фотографии

Страница содержит цену/«Цена по запросу», разрешённое местоположение, заполненные характеристики, описание, галерею и связь с Юлией. На телефоне сводка с ценой и звонком располагается перед фотографиями; закреплённых элементов, закрывающих содержимое, нет. Площадь участка показана в сотках, а исходные единицы хранения сохраняются. Название, цена, адрес и преимущества не дополняются вымышленными сведениями.

Порядок `[[photos]]` сохраняется. `cover` выбирает начальную фотографию, не переставляя список. Миниатюры переключают фото, стрелки идут по кругу, счётчик сообщает номер и количество. Главное фото открывает крупный просмотр в нативном `<dialog>`: кнопка закрытия и Escape, фокус внутри окна и возврат к исходной ссылке, стрелки клавиатуры. В увеличении используется `object-fit: contain`, без обрезания. С одной фотографией стрелок нет; без фото — нейтральная заглушка. При сетевой ошибке видны сообщение и ссылка на файл, переключение на другие фото продолжает работать. Жесты не перехватываются: вертикальная прокрутка остаётся браузерной.

Без JavaScript главное фото и миниатюры открывают файлы обычными ссылками; неработающие кнопки переключения и копирования скрыты. При отсутствии поддержки модального окна крупный снимок также открывается обычной ссылкой. Планировка, видео и тур показываются только при наличии данных: локальная планировка и безопасные HTTPS-ссылки, без сторонних виджетов.

Телефон берётся из `src/data/contacts.toml`. Необязательный `max_url` после подтверждения добавляет кнопку MAX на контактах и ссылку в блоке связи объекта. Пустое значение не создаёт ни кнопку, ни блок переписки. «Скопировать ссылку» использует Clipboard API в безопасном контексте; при запрете или отсутствии API появляется поле с выделенным постоянным адресом. Без JS адрес можно взять из строки браузера. В автоматическом тесте успех и отказ Clipboard API моделируются; системный буфер и реальный звонок проверяются отдельно на целевом устройстве.

## Клиентские сценарии и вопросы к Юлии

SEO-основа описана в [docs/seo.md](docs/seo.md): `public_url` в `site.toml`, отдельные title/description, canonical, Open Graph, JSON-LD сайта и автоматический sitemap. Локальный `base_path` не заменяет публичный домен. Индексация остаётся закрыта через `noindex, nofollow`; robots.txt в подпапке GitHub Pages намеренно не создаётся. Инструкция будущего запуска и ручные действия владельца находятся в этом документе. Проверки метаданных входят в `scripts/check.py` (`scripts/check_seo.py`).

На главной два различимых блока: покупатель может перейти к предложениям или обсудить покупку; собственник — обсудить подготовку к продаже. Отдельный повторяющийся блок услуг не добавляется. Сразу после первого экрана выводятся только отмеченные актуальные предложения. Если активные записи есть, но все `featured = false`, первый экран ведёт в заполненный каталог, а подборка остаётся скрытой. На главной не перечисляются неподтверждённые типы предложений.

На «Обо мне» сохранены Рязань, внимание к Советскому району и прежнее спокойное упоминание «Новоселья». Добавлены три шага: обсудить задачу, сравнить варианты/подготовку к продаже, определить дальнейшие шаги и отдельно обсудить необходимость специалистов. Это редакционная группировка уже имевшихся действий, а не гарантия результата или новый утверждённый регламент сопровождения.

Публичный FAQ содержит только ответы, вытекающие из материалов заказчика: можно обратиться на этапе выбора; территория в текущем тексте — Рязань; при отсутствии подходящих объектов можно рассказать о критериях и обсудить запрос. Для FAQ используется нативный `details`: работает без JavaScript и с клавиатуры. Тексты этих блоков также следует показать Юлии; служебных пометок на страницах нет.

Не публиковать без подтверждения Юлии ответы о бесплатности консультации, стоимости/порядке оплаты услуг, работе с объектами с других сайтов, одновременной продаже и покупке, точном объёме сопровождения и условиях привлечения специалистов. Отдельно уточнить, кто и в каком объёме проверяет документы. Действующие напоминания о территории, агентстве, наставнике, проверке документов, контактах и материалах остаются выше и в `docs/requirements.md`. Новые услуги, тарифы, гарантии и отзывы в интерфейс не добавлены.

Для MAX получите у Юлии проверенную ссылку на её контакт, проверьте адресата на целевом устройстве и внесите полный адрес в `max_url` в файле контактов. Не конструируйте адрес по номеру телефона. Сборщик принимает непустой HTTPS-адрес `max.ru` с путём, без учётных данных и нестандартного порта; это проверка формата, а не подтверждение существования/принадлежности профиля. После добавления ссылка появится в блоке связи главной, контактах и на актуальной странице объекта — пересоберите и проверьте эти места. `max_url = ""` или отсутствие ключа полностью скрывает этот способ связи. Телефон не меняется; автоматические проверки не звонят и не отправляют сообщения.

На этапе уточнения текстов заголовок заполненного каталога на первом экране изменён на «Недвижимость в Рязани — для жизни и ваших планов»; пустой каталог сохраняет отдельное приглашение связаться. Текст знакомства уточняет, что важно объяснять предстоящие шаги, без обещания результата. Формулировка о «Новоселье» не менялась. Телефонная карточка без MAX занимает всю доступную ширину: на компьютере имя и действие расположены рядом, на телефоне — друг под другом. Старого блока Telegram/WhatsApp нет ни в исходниках публичных страниц, ни в обычной сборке; не добавлять его как заглушку.

Проверки состояний главной, `featured`, FAQ и необязательного MAX входят в `py -3 scripts/check.py`. Дополнительная проверка в Chrome: `py -3 scripts/check_client_journeys_browser.py`. Она открывает главную, каталог, «Обо мне», контакты и тестовый объект при пустом каталоге, тестовых актуальных объектах с `featured` и без него в корне/подпапке на 360/390/1280 px. Проверяет CTA, FAQ, клавиатуру, отсутствие JS, заполнение ширины телефонной карточкой и отображение синтетического MAX на главной, в контактах и на странице объекта, не переходя в мессенджер. Новые скриншоты: `artifacts/screenshots/clarity-*`; прежние `clients-*` сохранены. Это эмуляция браузера, а не физический телефон.
